# Contributing

These rules apply to every change, whether written by a person or an AI agent. CI enforces the ones marked ⚙️.

## Comments

- ⚙️ At most 2 lines per comment. Longer explanations belong in `docs/` or an ADR.
- Explain **why**, not what. If the code needs a comment to say what it does, rename or simplify it.
- No multi-paragraph, banner or decorative comment blocks.
- No commented-out code; git keeps history.
- TSDoc only on exported public APIs, one sentence.
- ⚙️ `TODO`/`FIXME` must reference an issue: `// TODO(#123): replace with provider adapter`.

Enforced by `local/max-comment-lines` in `@sbi/config`.

## Modularity

- One package per responsibility (see the README layout table). Apps compose packages; packages never import apps.
- Import other packages only through `@sbi/<name>`. Each package's single public entry is `src/index.ts`; never import another package's internal files.
- Shared data shapes live in `@sbi/contracts`. Packages depend on contracts and interfaces, not on each other's implementations.
- External providers (recognition, LLM, renderers, storage) sit behind an adapter interface so they can be swapped.
- Keep files small and focused; prefer a new module over growing a large one.

## Code

- TypeScript strict mode; no `any`.
- Pin exact dependency versions (no `^` or `~`).
- Relative imports in TypeScript omit the file extension; all code is bundled (Next.js, tsup, Vitest).
- New behaviour ships with tests next to the code (`*.test.ts`).
- ⚙️ Before pushing: `pnpm lint && pnpm typecheck && pnpm test && pnpm format:check`.

## Product guardrails

- Never log or send photos, faces, precise location or raw tutor text to logs or analytics.
- Factual claims shown to learners must trace to a stored source, or be labelled as uncertain.
- Labels, formulas and quantitative visuals are deterministic; never generated by an image model.
- Third-party assets need a complete rights record before they can be published.

## Workflow

- One GitHub issue per branch and PR. Branch name: `feat/<ticket-id>-<slug>`, e.g. `feat/e0-3-comment-guideline`.
- PR description includes `Closes #<issue>` and the epic number. When a PR depends on another open PR, base it on that branch.
- Commit messages: short imperative summary line, optional brief body.
- No AI attribution: no `Co-Authored-By` trailers for AI tools and no "Generated with …" lines in commits or PRs.

## Environment

Node 22 (`nvm use`) and pnpm 10 (`corepack enable`).

## Branch protection for `main`

Configure in GitHub → Settings → Branches (rulesets require a paid plan on private repos):

- Require a pull request before merging, with at least one approval.
- Require the `Lint, typecheck, test, build` status check to pass, and branches to be up to date.
- Block force pushes and deletion.
