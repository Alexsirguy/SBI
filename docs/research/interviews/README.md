# Learner and family interviews (E1-2)

Goal: understand what makes people in each launch segment curious about everyday objects, how they look for explanations today, and what they need from a photo-to-lesson app before trusting it.

| File                                   | Use it for                                                    |
| -------------------------------------- | ------------------------------------------------------------- |
| [screener.md](screener.md)             | Recruiting and assigning participants to a segment            |
| [consent.md](consent.md)               | Parent consent, child assent and data handling                |
| [guide.md](guide.md)                   | The 45-minute session script, with per-segment variations     |
| [notes-template.md](notes-template.md) | One copy per session, filled in within 24 hours               |
| [synthesis.md](synthesis.md)           | Clustering notes into prioritised insights after all sessions |

## Plan

| Segment       | Who                                      | Target sessions | Format                          |
| ------------- | ---------------------------------------- | --------------- | ------------------------------- |
| Children 8–12 | Child with a parent or carer in the room | 4–5             | 30 min, video call or in person |
| Teens 13–17   | Teen alone; parent consents beforehand   | 4–5             | 40 min                          |
| Adults        | Curious adults, including non-parents    | 4–5             | 45 min                          |
| Families      | Parent and child together                | 3–4             | 45 min, includes a shared task  |

Aim for about 16–18 sessions in total. Stop a segment early if three sessions in a row bring up nothing new.

Each session ends with a short prototype walk-through. That walk-through doubles as the usability test for E1-3 (#12), E1-4 (#13) and E1-5 (#14). Run it in facilitator mode (`?facilitator=1`) so taps, corrections and the pre/post concept checks are logged against the participant code.

## Roles

- **Facilitator** runs the script and the prototype.
- **Note-taker** (optional) fills the notes template live. With no note-taker, the facilitator writes notes straight afterwards.

## Data rules

- Use participant codes (`C01`, `T01`, `A01`, `F01`) everywhere; keep the code-to-name key in a separate, access-controlled file.
- No photos or video of faces. Audio recording only with explicit consent, deleted once the notes are checked.
- Never commit raw notes, recordings or the code key to this repo. Only the anonymised synthesis lands here.
